# ADR-0003: 신뢰 점수는 온체인 기록에서 오프체인으로 재현 계산한다

- **날짜**: 2026-08-31
- **상태**: 개정 승인됨
- **개정일**: 2026-09-03
- **관련 기능**: character-agent-rebalancer
- **관련 요구사항**: R7.1, R7.3, R10.1, R10.9, R5.7

## 맥락

신뢰 점수는 자동 실행 경계를 움직인다(R5). 즉 **돈이 움직이는 경로에 영향을 준다.** 동시에 R10.1은 이 점수가 온체인 트랙레코드만을 원천으로 하고, 같은 기록이면 항상 같은 점수가 나오도록 요구한다.

점수를 어디서 계산하느냐가 검증 가능성과 비용을 동시에 가른다.

## 검토한 대안

1. **온체인에서 계산하고 저장한다** — 점수 자체가 위변조 불가능하고, 볼트가 점수를 직접 읽어 한도를 강제할 수 있다. 그러나 누적 성과·비용 집계를 컨트랙트에서 계산하려면 가스가 계속 들고, 점수 공식을 고칠 때마다 컨트랙트 업그레이드가 필요하다. 아직 공식이 확정되지 않은 단계에서 이 경직성은 비싸다.
2. **오프체인에서 계산하고 결과만 온체인에 기록한다** — 계산은 싸지만, 기록된 점수를 누가 계산했는지 신뢰해야 한다. 서명자가 새 신뢰 가정이 되고, "조작 불가능한 트랙레코드"라는 주장이 약해진다.
3. **온체인 원시 기록 + 오프체인 결정론적 재현** — 컨트랙트에는 판단·실행·비용의 원시 사실만 이벤트로 남긴다. 점수는 그 이벤트들을 입력으로 받는 순수 함수가 계산한다. 점수 자체는 저장하지 않는다.

## 결정

**3번을 채택한다.** 온체인에는 사실만, 점수는 공개된 순수 함수로 누구나 재현.

이유는 신뢰 모델이 가장 깨끗해서다. 사용자는 우리가 계산한 점수를 믿을 필요가 없다 — 체인에서 이벤트를 긁어 위임에 고정된 공식 버전의 함수를 돌리면 같은 값이 나온다. 점수 공식이 바뀌어도 과거 기록은 그대로이고, 분석 화면에서는 새 공식으로 과거를 재계산해 비교할 수 있다. R10.9(점수를 만든 기록을 함께 조회)가 자연스럽게 따라온다.

Keeper는 신뢰 점수로 낮아진 유효 임계값을 적용하고, 볼트는 **사용자가 서명한 autoThreshold와 하드캡**을 강제한다(R5.7). 오프체인 계산이 틀리거나 executor가 탈취되면 신뢰로 낮아진 경계는 우회될 수 있지만, 사용자가 서명한 절대 자동 실행 상한은 뚫리지 않는다. MVP에서는 이 둘을 각각 제품 정확성 경계와 컨트랙트 보안 경계로 구분한다.

## 결과

- 신뢰 점수 함수는 `packages/engine`의 순수 함수로 두고, 룰 엔진과 같은 결정론 테스트를 적용한다.
- 볼트 컨트랙트는 신뢰 점수를 저장하지도 참조하지도 않는다. 컨트랙트가 아는 것은 사용자가 서명한 한도뿐이다.
- 현재 위임은 `trustFormulaVersion`을 고정한다. 새 공식은 새 위임에서만 운용 경계에 적용하고, 판단 이벤트에도 사용한 버전을 남긴다.
- 이벤트 스키마가 사실상 API가 된다. 나중에 필드를 추가할 수는 있어도 의미를 바꾸면 과거 재현이 깨지므로, 스키마 변경은 신중히 다룬다.

## 2026-09-03 개정

신뢰는 볼트 전체가 아니라 캐릭터별로 계산한다. `Decided` 이벤트가 가진 `(delegationId, decisionId) → characterId`를 기준으로 실행·미실행·비용 기록을 묶고 `computeTrust(records, characterId, formulaVersion)`가 선택 캐릭터 기록만 사용한다. evidence 해석이 실패해도 인덱스 필드의 연결은 유지하며, 실망 이벤트도 characterId와 reportId를 직접 기록한다.

점수를 온체인에 저장하지 않고 원시 이벤트에서 재현한다는 기존 결정은 그대로 유지한다.
